# CineHOT 校园部署

让全校访问需要一台校园网络可达、能够持续运行的服务器。建议由学校信息中心提供服务器或虚拟机、固定 IP 和域名，再将网站通过 HTTPS 提供给校园读者。

## 先确认网络

请信息中心确认服务器的固定 IP、子网掩码、网关、校园域名、证书，以及哪些校园网段能访问它。仅有 `202.205.122.xx` 无法判断掩码、路由、NAT 或不同教学楼之间能否互通，不应据此直接设置 `/24`。

2026 年 10 月 15 日本机检查时，电脑使用 `192.168.31.52/24`，并没有直接配置该 `202.205.122.xx` 地址。这是当时的运行记录，地址可能变化；上线使用信息中心分配的实际地址。

## 部署与访问路径

1. 按[首次部署](README.md)在服务器运行 Docker Compose，设置 `PORT=127.0.0.1:3000`。
2. 让校园域名指向服务器，配置学校提供的 HTTPS 证书。
3. 使用 [Nginx 校园配置模板](../../deploy/campus/nginx.conf.example)反向代理网页端口，并将访问名单替换为信息中心确认的真实校园 CIDR。模板中的 `192.0.2.0/24` 是文档示例，不能用于实际校园名单。
4. 将 `.env` 的 `SITE_URL` 改为读者实际访问的 HTTPS 地址，设置 `TRUST_PROXY=true`，按部署参考重建服务。
5. 从学生 Wi-Fi、办公网和不同教学楼分别测试首页、文章、RSS 与后台登录页；无法连通时核对跨网段路由和访问名单。

读者访问路径是“校园域名 → Nginx HTTPS → 网页服务 → 内部 API”。API、PostgreSQL 和采集代理不需要向校园读者开放。若学校在反向代理前还有网关，先由信息中心确认真实客户端地址的传递方式，再配置访问控制。

## 数据迁移与日常运行

仓库不包含本地新闻数据库。需要保留已采集内容时，另行按[备份与恢复](../deploy.md#备份)迁移数据库及 `.data/`，在新服务器验证后再切换域名。服务器应持续运行并安排定期备份；本机睡眠或退出服务会中断采集。

参考：[Docker 单机生产部署](https://docs.docker.com/compose/how-tos/production/)、[Nginx 按 IP 和 CIDR 控制访问](https://nginx.org/en/docs/http/ngx_http_access_module.html)。
