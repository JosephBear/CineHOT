# CinemaHOT 运行维护

本说明用于检查采集、模型费用及内容是否正常。采集和模型由 worker 执行，读者打开网页不会触发模型调用。

## 当前本机试运行

2026 年 10 月 15 日按授权开启：17 个信源、固定 480 分钟采集、DeepSeek 默认模型，以及 `llm` 服务 20 次/分钟、60 次/小时、120 次/滚动 24 小时请求预算。外部推送保持关闭。该状态存于本机 `.env` 和数据库；新部署仍默认关闭采集和模型。

`COLLECT_ENABLED=true`、`MODEL_CALLS_ENABLED=true` 分别打开采集和模型；其他值视为关闭。修改 `.env` 后需要重新创建 Docker 容器，或正常停止并重新启动本机进程。

## 模型与费用

- 在 `/admin/models` 查看模型、调用情况与估算费用；在 `/admin/settings` 查看和修改请求预算。
- 当前默认模型读取 `LLM_BASE_URL`、`LLM_API_KEY`、`LLM_MODEL` 等私密配置，对应预算服务为 `llm`。切换为具名模型后，应核对其服务、单价和预算。
- 请求限制统计实际发送尝试，失败重试也会计数；滚动 24 小时不会在每天零点自动清零。任一请求预算为 0 会停止该服务的付费请求。
- 120 次请求不是 5 元金额硬上限。费用取决于输入、缓存和输出 token；估算值需要有效模型单价，实际扣费以 DeepSeek 账单为准。
- 首次导入历史文章与之后的增量采集应分开统计，首日费用不能直接当作长期日均费用。

本机 24 小时观察基线在工作目录 `work/24h-cost-baseline.json`，明日核对任务属于本机 Codex，不随 GitHub 或服务器部署迁移。观察读取后续 `receipt_attempts` 的尝试、token 与费用，不重跑模型。电脑睡眠或服务退出会缩短实际观察时间。

## 页面没有新内容时

1. 在 `/all` 查看全部资讯，首页只展示符合门槛的精选。素材入库不等于已发布。
2. 检查 worker、采集和模型开关；检查信源是否启用、最近抓取是否成功。
3. 检查模型 API 配置与预算。达到分钟、小时或每日上限时，队列需要等待配额恢复。
4. 查看正文是否可读、处理是否失败、素材是否通过筛选。不要通过提高分数或门槛绕过质量问题。
5. 若回执显示 `unknown`，先核对服务商调用记录和回执恢复流程，不要盲目重复请求，以免重复计费。
