# CineHOT 运行维护

本说明用于检查采集、模型费用及内容是否正常。采集和模型由 worker 执行，读者打开网页不会触发模型调用。

## 当前运行方式

主站在 Oracle 主机上持续运行：信源每 60 分钟采集一次（`site/site.ts` 的 `SOURCE_DEFAULTS.fixedIntervalMinutes`），默认模型为 DeepSeek，`llm` 服务的请求预算为 20 次/分钟、500 次/小时、2000 次/滚动 24 小时。外部推送保持关闭。这些状态存在服务器的 `.env` 和数据库里；新部署仍默认关闭采集和模型。

`COLLECT_ENABLED=true`、`MODEL_CALLS_ENABLED=true` 分别打开采集和模型；其他值视为关闭。修改 `.env` 后需要重新创建 Docker 容器。

## 站外探测

`.github/workflows/probe.yml` 每小时从 GitHub 的服务器检查一次线上站点：健康接口打不开，或者超过 6 小时没有收录新文章，这次运行就失败，GitHub 会自动发邮件给仓库所有者。它不在主站上运行，所以主机整个宕机、断网或采集停了，都能发现。

- 探测地址在仓库的 Actions 变量 `PROBE_URL` 里（Settings → Secrets and variables → Actions → Variables），没设时用 `https://cinehot.bear.opik.net`。换域名时改这个变量。
- 失败邮件的收件设置在 GitHub 个人设置 → Notifications → Actions 里，默认只在失败时发。
- 手动跑一次：仓库 Actions 页选“Probe”，点 Run workflow。
- 定时工作流在仓库 60 天没有提交时会被 GitHub 自动停用，停用前也会发邮件提醒。

站内告警（停止收录、worker 停了、预算耗尽、信源连续失败）仍只写进 worker 日志，不对外发送。

## 模型与费用

- 在 `/admin/models` 查看模型、调用情况与估算费用；在 `/admin/settings` 查看和修改请求预算。
- 当前默认模型读取 `LLM_BASE_URL`、`LLM_API_KEY`、`LLM_MODEL` 等私密配置，对应预算服务为 `llm`。切换为具名模型后，应核对其服务、单价和预算。
- 请求限制统计实际发送尝试，失败重试也会计数；滚动 24 小时不会在每天零点自动清零。任一请求预算为 0 会停止该服务的付费请求。
- 日常上限 2000 次/滚动 24 小时（2026-10-24 起；此前 1000 次时积压旧文章约 14 小时用完，每天只能处理 170–200 篇）。2000 次请求不是金额硬上限，按评测时单价约每天 6 元。费用取决于输入、缓存和输出 token；实际扣费以 DeepSeek 账单为准。
- 配了向量服务后（见[事件归组](../grouping.md)），归组会另外按次调用向量接口，对应预算服务为 `embedding` 或 `dashscope`。
- 首次导入历史文章与之后的增量采集应分开统计，首日费用不能直接当作长期日均费用。

## 页面没有新内容时

1. 在 `/all` 查看全部资讯，首页只展示符合门槛的精选。素材入库不等于已发布。
2. 检查 worker、采集和模型开关；检查信源是否启用、最近抓取是否成功。
3. 检查模型 API 配置与预算。达到分钟、小时或每日上限时，队列需要等待配额恢复。
4. 查看正文是否可读、处理是否失败、素材是否通过筛选。不要通过提高分数或门槛绕过质量问题。
5. 若回执显示 `unknown`，先核对服务商调用记录和回执恢复流程，不要盲目重复请求，以免重复计费。

## 日志、备份和更新

Docker 日志：

```sh
docker compose logs --tail=100 api worker web
```

停止 worker 时保留最长 210 秒退出时间，让进行中的付费调用收尾。不要把日志、密钥、数据库或 `.data/` 上传到 GitHub。

升级按 [Oracle 部署模板](../../deploy/oracle/README.md) 执行，它会先按实际挂载备份并做恢复验证。`VERSION` 表示项目版本，接口版本独立维护。

## 历史记录

- **2026-10-15 至 10-18 本机试运行**：17 个信源，先后为 480、360 分钟采集，预算 120 次/滚动 24 小时。已结束，现在不再使用本机运行。
- **2026-10-16 一次性月度回填**：用户授权本轮历史回填不受 120 次限制，共 3681 次模型请求，按回执 token 估算 9.54 元。之后通过迁移 `0084_budget_daily_reset_at.sql` 新增的 `budgets.daily_reset_at` 把当日额度重新起算一次；该字段默认为空，空值时行为与上游一致，那次起算早已不再影响计数。
