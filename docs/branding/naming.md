# CineHOT 命名与现有部署

项目品牌、网页英文名、文档统一为 **CineHOT**；GitHub 仓库为 `JosephBear/CineHOT`。需要小写的 npm 项目名和新镜像仓库使用 `cinehot`，新镜像地址为 `ghcr.io/josephbear/cinehot-app:<标签>`。旧镜像保留供回退，不重写已经发布的标签。

## 现有部署的兼容边界

既有部署仍使用 `cinemahot` 的 Compose 项目、数据库用户、数据库名、卷名和 `/opt/cinemahot` 目录。这些标识对应已有新闻、回执和备份，不可用全局字符串替换迁移。旧版本升级文档中的旧镜像地址保持有效；历史镜像里的 `upgrade.sh` 使用旧仓库；本次源码中的脚本已改为拉取新镜像仓库，必须与新版本镜像一起使用，不可用新脚本安装仅存在于旧仓库的历史版本。

MCP 的 `cinemahot_` 工具前缀保留，避免现有客户端断连；`@aihot/*` 和 `AIHOT_*` 是上游框架接口，保留原名和开源署名。忽略文件中的旧密钥文件名也必须保留，以免误上传旧配置。

本次源码改名不启动采集、不改变模型配置、不迁移数据库、不改变代理域名。校园站如果仍代理 VPS，显示名称取决于 VPS 实际运行的镜像，更新校园目录不能更新 VPS 页面。

新镜像部署前须单独安排：确认镜像构建成功、备份、沿用现有 Compose 项目及卷，仅更换应用镜像引用，然后验证页面与 worker。校园镜像模式下不得启动校园 worker。不要删除旧目录、卷、历史标签或备份。
