## 本地标注工具

`scripts/label-selection.ts` 从当前信源抓取近期真实文章，在本机网页里逐条标注，再导出评测用的 `.data/gold.jsonl`。只读取公开页面，不连数据库、不调用模型、不使用付费正文服务；样本与标注都在 `.data/labeling/`，不进 Git。

```sh
node --env-file=.env scripts/label-selection.ts collect --per-source 3 --days 45 --max 200   # 每个信源取近45天最新3条
node --env-file=.env scripts/label-selection.ts serve                                       # 打开 http://127.0.0.1:4321/ 标注
node --env-file=.env scripts/label-selection.ts export                                      # 或在网页里点“导出”
```

本机海外信源需要出网代理时，在命令前加 `EGRESS_PROXY_URL=…`（见[信源侦测](../../scripts/source-discovery/README.md)的“本机转发代理”）。重新 collect 会保留已标注条目；每条按编号固定分到开发集或留出集（约四分之一留出）。导出时 `samplingStratum` 取信源标签，便于看错在哪一类。

## 人工标注

1. 打开原文，确认内容与发布时间；不要只凭标题判定。`materialStatus` 表明现有材料仅是标题或订阅摘录。
2. 在 `decision` 填 `select`（该选）、`reject`（不该选）或 `either`（两可），并写 `reason`。不要把同一新闻的重复报道直接当作噪声，当前评分评测不含最终归组去重。
3. 阅读材料不可访问、事实无法确认时，保留 `pending`，不要猜标签。完成的样本再把 `annotationStatus` 改为 `reviewed`。
4. 补充其他信源、中文媒体、影展/协会及难例；复核分级与日期。已有 development/holdout 划分仅便于组织，不代表样本已独立、已去重或已完成盲测。相同事件应放在同一份中。
5. 将已完成条目整理为 `docs/selection.md` 规定的 `.data/gold.jsonl`：保留原始标题与日期，补齐实际阅读材料，写入 `gold.decision`；不要将这里的扁平待标注 JSONL 直接当作评测输入。

## 之后的评测

人工标注完成且明确启用模型、配置好服务商与预算后，使用已有评测脚本：

```sh
node --env-file=.env scripts/eval-selection.ts --gold .data/gold.jsonl --split development --label 'CinemaHOT 首轮人工标注'
node --env-file=.env scripts/eval-selection.ts --gold .data/gold.jsonl --split holdout --label 'CinemaHOT 留出集验收'
```

评测会调用模型并可能计费，本次没有执行。对比查准率、查全率、F1、覆盖率、完整准确率和错例；先调整标准，再决定是否调整门槛，最后用未参与调参的留出集验证。`industry/gold.example.jsonl` 仅为明确标注的虚构格式示例，不能用于证明真实质量。

首轮校准前的 T1/T1_5/T2 门槛是上游初始值 60/65/76，`understandFloor` 为 50。

## 首轮校准结论（2026-10-19）

**样本**：用 `scripts/label-selection.ts` 从当时登记的信源抓取近45天的186条真实文章（67个信源；官方与媒体各约一半；中文24条），站长逐条标注：该选58、不该选59、两可69。按编号固定分出开发集138条、留出集48条；去掉两可后，计入指标的开发集86条、留出集31条。

**评测脚本修正**：上游 `scripts/eval-selection.ts` 不运行写作步骤，`normalizeAnalysis` 因缺少标题摘要把所有未被拦截的条目判为“不确定”，任何门槛下都不会入选。现改为评测中以预筛 PASS 代替写作结果，入选规则仍只在 `normalizeAnalysis` 一处。

**标注反映的读者标准**：师生要的是能学到创作方法、看懂行业变化的内容——创作者访谈与制作幕后、镜头与布光方法、创作者用得上的器材与软件、重要影展获奖结果、头部AI模型的重大发布；不要机构事务（任命、入选、换届）、流程公告（入围名单、开幕式、座谈会、展位）、企业营销与客户案例、只有版本号的更新日志、播客节目单、品牌社媒短视频。官方信源的入选率（34%）明显低于媒体（64%）。

**标准调整**：预筛放行头部AI实验室与生成平台的旗舰模型发布与重大能力更新、电影产业与市场动态，并明确拦截AI公司的企业客户案例、开设办公室、合规认证与选举政策表态；评分提示词的读者改为以学电影与泛影像的师生为主，新增“创作者访谈与制作幕后”“头部AI旗舰发布”两类价值，以及版本号更新日志、企业产品营销、客户案例、机构事务、流程公告、播客单期、品牌社媒短视频、与影像无关的AI公司动态八类噪声。五轴与类型权重未改。

**结果**（同一批标注，模型 deepseek-flash）：

| | 改标准前 | 改标准后 |
|---|---|---|
| 该选条目的分数中位数 | 42 | 55 |
| 不该选条目的分数中位数 | 22 | 15 |
| 开发集（统一门槛32）查准率 / 查全率 / F1 | 0.86 / 0.67 / 0.75 | 0.78 / 0.75 / 0.77 |
| 留出集（统一门槛32）查准率 / 查全率 / F1 | 0.45 / 0.50 / 0.48 | 0.58 / 0.70 / 0.64 |

原门槛 60/65/76 在改标准后的开发集上只选出约6%，覆盖不到该选内容的一成。按分级分别设门槛的最好组合（如 T1 24 / T2 20）没有明显优于统一门槛，因此三级统一为 **32**，`understandFloor` 相应由 50 降为 **25**。

**仍存在的问题**：预筛对部分头部AI新闻（Gemini、Anthropic、Runway 加入安全联盟）和《给阿嬷的情书》海外热度仍判为无关；部分更新日志与推广内容（Midjourney 更新记录、AI课程推广、播客节目）仍有较高分；留出集样本少，结论有波动。正式运行一段时间后，用真实采集数据补标一批（尤其是留出集）再评测。两轮评测共约1190次模型请求。
