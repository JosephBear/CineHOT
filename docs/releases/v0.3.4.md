# CineHOT v0.3.4

2026-11-20。Oracle 升级与恢复演练，运维改进；读者页面没有变化，没有新的数据库迁移。

## 内容

- **Oracle 升级入口** `deploy/oracle/upgrade.py`：从运行中的容器读出 Compose 项目、配置文件顺序和实际挂载，停写前先比对现有配置和候选配置。旧的 VPS 脚本遇到非标准挂载、叠加配置或自定义 Compose 时，会在停写前退出，避免覆盖模型或端口配置、把错误的卷备份成空归档。
- **备份必须先验证**：按停写容器的实际挂载打包 `/data` 并核对；在独立的 PostgreSQL 实例里完整恢复数据库并核对业务表行数，通过后写入 `RESTORE_VERIFIED`，之后才迁移、启动网页、恢复 worker。
- **发布前演练**：每次发布前，两个原生 runner 都会启动待发布镜像，跑一遍测试项目的升级、恢复和网页访问。ARM64 从 Oracle 上 v0.3.2 对应的固定镜像重建基线，升级后迁移记录由 65 增至 93，原文章与文件可读；再从备份单独启动旧版站点，验证健康接口和列表页。

## 更新步骤

按 [Oracle 部署模板](../../deploy/oracle/README.md) 的“已有 Oracle 项目升级”执行。升级后核对 worker 正在运行、`.env` 里 `COLLECT_ENABLED` 和 `MODEL_CALLS_ENABLED` 为 `true`，并确认有新文章入库：升级脚本只负责换镜像和迁移，不会替你打开采集。

## 验证与限制

演练只在 GitHub runner 上用合成数据进行，不代表线上数据的规模和耗时。
